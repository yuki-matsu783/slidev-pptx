## 成果物

順番は「依存 → 単体で通る層 → fixture の実物合わせ → e2e で通る層 → デッキ側」。各段でコミットを分ける。

1. **依存と置き場**（最初に。ここが入れば i0001-03 の検査が回せる）
   - `pnpm-workspace.yaml` に `packages: [packages/*]`
   - ルート `package.json`: devDependencies に `vitest` `@xmldom/xmldom` `jszip` `pptxgenjs`、
     `"slidev-addon-pptx": "workspace:*"`、scripts に `"test": "vitest run -c tests/vitest.config.ts"` と
     `"test:e2e": "vitest run -c tests/vitest.e2e.config.ts"`、`export:pptx` を `slidev-pptx export slides.md` に、
     `export:pptx-image` を `slidev export --format pptx` に
   - `packages/slidev-addon-pptx/package.json`（name、`bin: { "slidev-pptx": "bin/slidev-pptx.mjs" }`、Slidev アドオンの設定）。
     `bin` は shebang つきの素の `.mjs` にして、ビルド無しで `node_modules/.bin/slidev-pptx` から起動できるようにする
     （`tests/cli/export.test.ts` は `.bin` を子プロセスで起動する）。`exports` は絞らない（検査は `src/**` を相対パスで import する）
   - `pnpm install` を走らせて `.bin` のリンクを作る。生成物（`dist/`）は作らない方針なので `.gitignore` は触らない
2. **ブラウザ無しで通る層**（`pnpm test` が緑）
   - `src/types.ts`（Capture / Report / CheckResult と要素の型。`src/patch/index.ts` の `Patch` `PatchContext` もここで要るので先に）、
     `src/build/{units,sanitize,names,fonts,notes,layout,masters,convert}.ts`、
     `src/patch/{zip,index}.ts` と `patches/*.ts`（後処理 1〜7）、`src/opc/check.ts`（C1〜C14）
   - 実装の順は検査の依存順: types → units → sanitize → names → fonts → notes → layout → masters → patch/zip →
     patches → opc/check → convert。`replaceMaster` は no-op でも `MasterSwap` の型と `findRelByType` を実装し、
     `tests/patch/replaceMaster.test-d.ts` の typecheck を通す
3. **fixture と検査の実物合わせ**（e2e に入る前に）
   - `tests/README.md` の「設計へ書き戻す候補」と「フェーズ 4 で最初に確かめること」を 1 つずつ実物で確かめ、
     検査の期待値が実物（Slidev / PptxGenJS / xmldom の実際の出力）と食い違っていれば、最小の再現を残したうえで検査を直す
   - 設計の記述が実物と違っていた箇所は、`tests/README.md` に書き足し、設計（と必要なら `wip/research/summary.md`）の
     訂正を親に依頼する（どちらもこのチケットの範囲外）
4. **e2e で通る層**（`pnpm test:e2e` が緑。playwright-chromium が要る）
   - `src/collect/index.ts`（`collect` を 1 関数に閉じる。`page.evaluate` に渡す。`zoom` は computed の `scale` を読む）
   - `src/export.ts`（§1 の流れ。画像の取得、置き換えの撮影、記録の書き出し。待機列は `tests/e2e/helpers.ts` と同じ）

   - `slides.md` に `addons: [slidev-addon-pptx]` と `fonts: { sans: '游ゴシック', mono: 'Consolas', local: [...] }`、
     PPT 部品を使うスライドを 1 枚
6. **設計の「要確認」への答え**（native-export.md §11 の 1〜7）を、検査の結果として `tests/README.md` に 1 行ずつ書く

## 決め方

- 検査を緩めない。検査が**設計**と食い違っていたら、設計の側を正すか検査を直すかを親に相談する
- 検査が**実物**（Slidev / PptxGenJS / xmldom の実際の出力）と食い違っていたら、実物を再現する最小の証拠（スクリプトか出力の抜粋）を
  `tests/` に残したうえで検査を直す。設計が実物と違っていた場合は、あわせて設計の訂正を親に依頼する
- design-feedback の子はこのチケットからは切れない（親 `i0001` の `feedback:` に種類を並べる改版が要り、親チケットは範囲外）。
  「設計へ書き戻す候補」は `tests/README.md` に溜め、フェーズの終わりにまとめて親に依頼する
- 設計に無い判断（`tests/README.md` の候補一覧）は、実装で先に決めて README に書き、上の依頼に含める
- PowerPoint 実機（Windows）での開封は人のレビューで。修復が出たら OPC 検査に規則を足す
- `node` は PATH に無い環境がある。scripts は `pnpm` 経由で呼ぶ
